## Actual operation and policy

The app's reviewed flow uses a fixed optional local photo_ocr_config.json, plus the actual existing ai_provider.json and ai/config.json from its source root. These files are not changed by this increment. Missing/malformed policy or an Aster provider selection refuses this first optional adapter. The existing provider handshake and model policy remain separate; OCR is an explicit perception operation, never a reasoning-model fallback.

The operation captures one group under its ledger writer lock, including every original saved view, exact image hashes/bytes/types, current revision, full state/review digests and actual provider/AI configuration byte hashes. The complete OCR configuration's exact raw-byte SHA256 is bound separately. Changing whitespace in that file changes the selection; qualification uses a separate canonical settings/closure digest to avoid circular hashes.

The adapter then releases the ledger lock and creates one exclusive private OCR run lock. Views are serial. It reads saved originals by hash from the bound store; arbitrary input filenames are not passed to OCR. The caller must reacquire its ledger lock and revalidate current state, every original, policy and selection before persisting or approving a candidate. Approval is one explicit reviewed inventory transaction; it does not convert OCR into existing human observations.

Unavailable selection raises OcrUnavailable before runtime scans, native import, decoding or launch. There is no network, HTTP vision, generic model, executable search through PATH, automatic installation, provider call, training, hidden fallback or inventory adoption.

## Qualified runtime admission and trust

run_ocr(config, capture, *, store_root, selection_sha256, selection_bytes, cancel=None) requires the actual bounded configuration bytes, not a caller's unattached hash declaration. load_config validates strict UTF-8 JSON, duplicate/unknown keys, integer-only numbers, depth/nodes/bytes, portable paths and closed schemas. Configuration is at most 64 KiB.

The selection specifies exact absolute local runtime_root, relative python/engine/model/Pillow roots, hash-pinned Python/runtime bytes, declared Pillow/Tesseract/OS versions, a complete bounded file manifest, the three adapter/worker/guard source hashes and this catalog digest. The English model is pinned by actual binary SHA256. No model hash or installed executable is guessed. Runtime relative paths allow at most eight ASCII components and 240 bytes, with no traversal, colon, network, backslash, reserved Windows devices including COM0/LPT0, case collisions, symlink/reparse or hardlinked files.

The runtime manifest allows at most **1,010 files and 267,108,352 bytes**. This reserves five pins for the three source files, request and original input, and nine pins of at most 8 KiB each for qualification records inside the guard's 1,024-file/256 MiB pin budget. A compact isolated Python/Pillow/Tesseract installation must fit; broad user Python environments can be refused. All actual files must match the listed closure. No unbounded discovery or implicit --version command is used.

Qualification's exact keys are format, runtime_sha256, code_sha256, catalog_sha256, engine_version, pillow_version, os_version, receipt_root, tests. Its format is photo-ocr.qualification.v1. Each test descriptor has exact id, status, receipt_path, receipt_sha256 and receipt_bytes (1..8192). Nine required identities are containment, timeout, overflow, decode-negative, pixel-positive, pixel-negative, pixel-ambiguous, pixel-conflict and project-isolation. Every required test must declare passed; failed/unrun refuses before native work.

The adapter reads and hashes each included actual local test receipt, not just its declaration. Each closed receipt has format photo-ocr.qualification-test.v1, id, status, the six selection binding fields, elapsed_ms, peak_job_memory_bytes, owned_job_empty, loaded_runtime_paths and test_only. The selection fields bind runtime/code/catalog/engine/Pillow/OS. Actual cleanup must be declared true, test_only false, and the union of loaded paths must include the pinned Python, engine, model and compiled Pillow decoder.

These are **operator-supplied, unauthenticated claims**. Valid bytes and hashes do not prove that observations happened. A reviewer must inspect actual runs, loaded DLL/codec/model observations, negative behavior and cleanup before selecting these exact bytes. No helper produces a passed qualification record. Installation roots must remain trusted, serialized and read-only during operations: file locks deny replacement/deletion of pinned files, but directory handles are not a security boundary preventing new file creation. Before/after exact manifest checks supplement, rather than prove, absence of loader races. The guard is a resource guard for trusted pinned binaries, not a security sandbox.

## Native worker and resource limits

Windows 10+ creation-time PROC_THREAD_ATTRIBUTE_JOB_LIST is required. The process must be outside an ambient Job; unsupported/nested environments fail closed, with no breakaway attempt. The parent starts exactly the pinned Python with -I -S -B and the pinned worker/request paths. A fresh unnamed Job owns the Python worker, Pillow decoding and its Tesseract descendant from creation. Membership is checked before resuming the suspended primary thread.

The Job permits two processes and caps **aggregate committed virtual memory at 512 MiB**. This is not physical-memory/RSS measurement. PeakJobMemoryUsed is recorded; RSS is unknown. Thread environment limits OMP_THREAD_LIMIT=1 and OMP_NUM_THREADS=1 are hints to the engine, not an OS thread/CPU quota. Only explicit child standard handles are inherited. Bounded overlapped guard pipes and bounded worker readers drain stdout/stderr concurrently. The native argv is fixed: derived.png, stdout, --tessdata-dir, -l eng, --oem 1, --psm 11, tessedit_create_tsv=1, load_system_dawg=0 and load_freq_dawg=0. No expected label, user filename, arbitrary config file, dictionary, whitelist or metadata supplies an answer.

Input limits are one MiB per view, two million pixels, six views per group and single-frame PNG/JPEG/WebP only. Pillow header geometry/frame checks precede load; warnings, bad containers and decoding failures refuse. A fresh RGB PNG strips copied EXIF/comments/labels. Transparency is composited over white. No rotation, crop, upscaling, OCR reading-order promise or EXIF orientation inference is performed. The identity-no-exif transform means boxes refer to unrotated decoded pixel coordinates; an EXIF-rotating viewer can display another orientation.

One derived PNG is limited during writing to eight MiB. Engine TSV is at most 256 KiB, stderr 16 KiB, wrapper JSON 64 KiB, words 128 total, token text 96 UTF-8 bytes. TSV header/columns/pages/identities/boxes and finite diagnostic confidence are validated. Confidence is stored as integer thousandths; it is not identity probability. A diagnostic value below 85/100 prevents resolved confirmation without asserting a calibrated error rate.

Each owned image Job has a five-second deadline including guard preparation, decoding and OCR. The native child has a four-second local deadline. Group admission starts a 35-second deadline before closure/code hashing and checks cancellation/deadline between bounded 64 KiB file reads and directory entries. Synchronous OS file/setup calls are not hard preemptible. Thus **total API wall time is not a proven hard 35-second cap**; termination/reaping has a separate bounded guard attempt and can fail. Receipt elapsed_ms is the sum of owned guard intervals, not the full admission/approval time. No timing or peak value has been measured here.

JobObjects provide no disk quota. Private scratch is bounded by known writes: one original <=1 MiB, one request <=8 KiB, one derived PNG <=8 MiB, fixed filenames and bounded pipes. No arbitrary native output file is requested. Existing scratch must be empty; one owned image directory exists at a time, keeping expected written bytes below 10 MiB, within the proposed 64 MiB scratch allowance. Trusted dependency temporary files are directed to that directory through TMP/TEMP. Qualification must observe any unexpected writes; a scan is not presented as an OS quota.

Timeout, cancellation, overflow or setup failure terminates and reaps only the returned owned Job/process. The guard requires confirmed owned-process exhaustion and terminal pipe state, never global process names/PIDs. Unconfirmed cleanup permanently refuses later guarded launches in that process. Any failed adapter run preserves its lock/scratch for explicit local inspection; it never removes a stale lock or automatically retries. Cleanup success permits removal of only the owned scratch directory. Unrelated projects/processes are never terminated.

## Catalog and strict private receipts

The catalog contains the ten previously reviewed complete public NVIDIA codes: P3767-0000/0001/0003/0004/0005, P3768-0000, P3448-0000, P3449-0000 and 945-13450-0000-100/000. It distinguishes module, carrier and developer_kit. Orin full supported SKU evidence supplies documented memory; Nano module/carrier/kit records do not invent memory. Hardware manufacturing revision stays unknown; kit names' documented carrier revision is not an observed hardware revision.

Partial codes, lowercase/transcription confusions, O/0 or I/1 repair, unknown 699 part-number records and unsupported suffixes are unresolved. Words are not concatenated into a guessed code. Module plus carrier never implies kit. Different exact codes for the same role across any views remain conflicting; selected subsets cannot remove a recognized conflict. Unknown/partial code-like words and low confidence prevent resolved status. Review of all views and exact label boxes is necessary even for a candidate: OCR can produce wrong complete codes with high diagnostic confidence.

The closed photo-ocr.capture.v1 schema binds app_id (ideaforge or humanoidresearcher), project_id, root_binding, revision, item_id, state_sha256, review_sha256, provider_selection_sha256, ai_config_sha256 and all photos. HumanoidResearcher's existing provider identity humanoid-researcher is separate and is not silently aliased by this canonical ledger identity.

The closed photo-ocr.candidate.v1 receipt contains capture, raw selection digest, catalog digest, engine/runtime/model/code digests, one derived hash/geometry/TSV digest/word-box array per input, exact recomputed whitelist matches, unresolved/conflict status, integer metrics and explicit test_only. It is <=64 KiB. validate_receipt is pure: it checks strict types, every original/view, current capture/selection, current selected engine bindings when supplied, catalog, geometry, whole match set, status and metrics. It can validate history without an installed engine. Synthetic receipts explicitly say test_only=true; production approval refuses them unless an explicit test-only test policy is used.

Raw words and boxes can include private serial text; full receipts remain local. candidates returns only matched whitelist records with public manufacturer source facts plus fixed status/conflict messages/counts. Public inventory/result exports never include unknown strings, raw recognized words, runtime filesystem paths or binary photos. Matching/hashes verify included metadata; they do not authenticate manufacturer data or independently verify original pictures for Aster.
