# October 5 Aster reliability and versioned NewBrain update

## User-visible changes

- An explicitly configured outbound remote bridge can now run with the desktop
  open. Phone text enters a bounded queue and is committed by the same worker
  that owns desktop state. No second Store or job dispatcher is opened.
- Stable message IDs, commit-before-receipt/ack, duplicate/conflict checks,
  queue-full retry and shutdown behavior preserve exactly-once local insertion.
  A pending local confirmation defers remote text; phone messages cannot confirm,
  dismiss, execute jobs or alter files. Remote mode remains off by default.
- The isolated numeric component lab now stages learning and observer changes
  before publishing a complete bounded checkpoint. Capacity, write, fsync and
  replace failures preserve the prior live state/checkpoint. Exact observer
  records, including failed and unknown boundaries, can survive cold restore.

See [desktop/remote instructions](../remote-companion/README.md) and the
[component lab API and limits](../experiments/newbrain_adapter/README.md).

## What the NewBrain version update does

The experiment selects reviewed NewBrain commit
`df8c2bc9dd6359c5a20b14baf0b3dd9982c5f5ef`. Its eight selected component/test/notice
files are byte-identical to the original `bd0c5a34ade90470fb2bb0025af30cf4a51881bd`
snapshot. Both immutable source versions remain. Explicit v1/v2 migration and
rollback preserve owner, learner coefficients/receipts and complete observer
history; ordinary restore still refuses cross-pin state.

The repin itself adds no intelligence. Reliability is improved in Aster-owned
adapter code. Production `aster.backend` stays unavailable and has no hidden
Qwen, provider or reasoning fallback. No Aster identity/store or voice asset is
replaced, and no other person's state is copied.

The newer generic decision-retention075 source is preserved separately as an
unqualified candidate. Five required published modules are absent; private
runtime, model/input and gold bindings are excluded. Its [admission audit](../experiments/newbrain_candidate/README.md)
correctly returns exit 2. These source checks do not reproduce upstream tone
results, qualify hearing/conversation or turn an incomplete private repository
into a runnable brain. Source rights/provenance and all file hashes are retained.

## Release gates and limitations

This change was published as a draft for independent review. The corrected-source
Windows/Linux outcomes are retained below; no pending CI is counted as a pass.
The workflow now saves all stage logs, source manifests and receipts as repository
Actions artifacts, and also prints complete logs for later archival. Final review
and CI must precede merge.

The remote test uses a real loopback HTTP server and synthetic test tokens/text,
not a public relay, deployed phone client or real pairing. No microphone/camera
permission, startup registration, paid service or user settings change occurred.
Checkpoint atomicity requires a trusted single writer/local filesystem; power-loss
durability and hostile same-user filesystem interference are not qualified.
Legacy direct `.model` mutation remains explicitly nontransactional for old lab
callers; the safe adapter methods are the supported reliability path.

## Later Windows timing failure and explicit timing checks

The evidence-only head `37554bf4a111174c278062c954cceb1c0248c1c0` later failed
one Windows remote case at its five-second prompt-count wait. The other remote
cases, including native Tk, passed. The old fixture did not retain counts or
poller state at the deadline, so that result alone does not prove loss, deadlock
or slow-host throughput. The negative result and full jobs remain in
[`ci-evidence-rerun/`](../test-results/2026-10-05-upgrade/ci-evidence-rerun/).

The revised test-only wait observes committed count, acknowledgement completion,
queue depth, state-owner liveness and poller status under a bounded 30-second
correctness deadline. It fails immediately for a dead worker or stopped poller,
keeps every exactly-once/no-job/single-writer assertion, and retains progress and
actual timing rather than retrying until green. A deterministic injected receipt
delay exceeding five seconds verifies complete delivery and bounded shutdown.
No production timeout, queue, locking or polling setting was changed.

Correctness is separate from latency: a newly submitted message with the desktop
and idle poller already open has explicit receipt and acknowledgement assertions
of at most 20 seconds (two existing ten-second poll intervals). Startup backlog
tests are labelled separately and do not claim that latency qualification.
These are loopback fixtures, not public-network or physical-phone guarantees.
Independent review and fresh exact-head CI still apply to this test correction.

The final local timing-correction aggregate is in
[`aggregate-04/result.json`](../test-results/2026-10-05-upgrade/aggregate-04/result.json).
The companion suite now has 35 cases, including deterministic delayed delivery,
bounded diagnostics, immediate dead-worker/stopped-poller refusal and the
already-open 20-second goal. Independent companion checks also passed all
applicable cases. Full timed observations and exact test hash are retained in
